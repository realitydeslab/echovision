## Keep / repair / remove

| Area | Decision | Reason |
| --- | --- | --- |
| Unity 6000.3.24f1 + resolved AR packages 6.4.3 | Keep | Compiles and exports on the installed toolchain; don't mix another package experiment into this recovery. |
| Remove obsolete `-ld64` flag | Keep | Xcode 27 linker compatibility. |
| AR pose and custom background | Repair together, iOS 27 only | Native ARKit absolute view pose plus inverse display transform; clone the existing background material and retain its shader/depth/texture bindings. Real screenshots confirm shelf/mesh registration. |
| GPU recording, BGRA format, bitrate | Keep and repair | Wait for an actual graphics fence; acquire buffers from the encoder pool so a buffer retained by AVAssetWriter cannot be overwritten. |
| Automatic 4K camera input | Keep, explicitly requested | Recording override separate from user preference; works for Mono and Stereo capture; restore the exact previous ARKit video format/HDR setting. |
| Recorder lifecycle/audio | Repair | Serialize append/finalize; sample-count timestamps; prevent duplicate start; recover from failed start; stop on pause; prevent microphone feedback. |
| Optional helpers / commented-out implementations | Remove | No callers; reduce code surface. |
| CPU fallback | Keep | Covers devices/backends without supported BGRA/fences; timestamp captured with its own readback callback. |
| Recording dimensions after rotation | Fixed movie dimensions, fit live view | Container dimensions cannot change mid-file; preserve image aspect with borders rather than stretching. |
| visionOS | Preserve existing separate-target state | Not part of this iOS recovery; see `Tools/VISIONOS.md`. |

4K refers to **ARKit camera input**, not an assertion that the saved screen-aspect video is 3840×2160. Output dimensions are recorded in the start log and checked with ffprobe.

## Evidence so far

- Unity CLI baseline export: success, Unity 6000.3.24f1.
- Xcode 27 baseline build and installation to iPhone 15 Pro / iOS 27: success.
- Unity CLI EditMode: **17/17 passed**, aspect preservation, 4K policy transitions and Mono/Stereo camera event transitions. Final-source rerun: 2026-09-21 16:16 UTC. These are not physical AR alignment tests.

The device walker runs automatically only in the dedicated **iOS Recovery Tests** development profile with `ECHOVISION_DEVICETEST`. The shipping iOS profile has neither flag. It exercises all four explicit interface orientations, recording on/off, stereo start, and orientation/mode changes inside a recording. Forcing orientations is diagnostic; the shipping autorotation policy is a separate check. Inspect generated files and screenshots; nonzero submission counters alone are not a visual pass.

## Release gate

Verified on iPhone 15 Pro / iOS 27:
- All supported Mono interface orientations (Portrait, LandscapeLeft, LandscapeRight), recording off/on; Stereo locked to LandscapeLeft; live Stereo -> Mono Portrait -> Mono Landscape -> Stereo during one movie.
- PortraitUpsideDown is **requested but iPhone returns Portrait**. This is not counted as a successful upside-down display. No connected iPad was available.
- 4K native input enters 3840x2160@30 and restores exactly 1920x1440@60 at every stop; GPU selected throughout.
- Corrected AR pose matches native view at render completion; custom background, mesh screenshots and decoded GPU movie orientation agree. The uncorrected control had 90-degree/180-degree pose discrepancies and an incorrect landscape background transform.
- Clean test pass: 5 movies, 90/92/94/93/272 decoded frames matching submissions, zero dropped frames, HEVC + AAC 24 kHz stereo; all full-file decodes pass. Audio/video end-time differences 36–118 ms. Artifacts: `Build_RecoveryArtifacts/device-clean/`.
- The test screenshot initially used an absolute path unsupported by the mobile CaptureScreenshot API; switched to explicit PNG writes. PNG encoding blocks the main thread, so the test now allows 250 ms of normal capture before stop.
- Guard invalid human-stencil descriptors before AR Foundation creates a texture wrapper; previous NotSupportedException catch did not prevent null-native-texture exceptions.
- GPU stop waits for each destination copy rather than consulting a same-frame cached fence state.

Real sound-trigger test passed: Mac speakers played 440 Hz in two-second on/off intervals; iPhone detected approximately 441 Hz and raw RMS around 0.05 (trigger volume around 0.19–0.26, existing threshold 0.02). Actual emitter-index transitions occur with Mono/Stereo and recording off/on. The GPU movie shows purple waves expanding over the bookshelf during the tone and fading in silence. Existing audio analysis is retained. Mac volume was restored from the temporary test setting 65 to its original 38. See `audio-trigger-summary.json`, `device-audio-10.log` and `audio-trigger-landscape.mp4` in `Build_RecoveryArtifacts/`. There were 27 actual emissions: Mono idle 14, Mono recording 9, Stereo idle 1, Stereo recording 3. Decoded movie audio measured 440.07 Hz.

Unity CLI shipping export (`iOS`, non-development) succeeded. Generated IL2CPP contains neither `DeviceStateWalk` nor `ARAlignmentDebugOverlay`. Signed Release archive succeeded at `Build_RecoveryRelease/EchoVision.xcarchive`; archive app installed on the iPhone. Full-access codesign verification passes. Release startup and on-device inspection are being checked; no upload has occurred.

Deployment minimum remains **iOS 26**, as in the pre-recovery migration (May 4 used iOS 17). Building with SDK 27 and choosing a minimum OS are separate choices; no older-device compatibility claim is made from this iOS 27 device test. Version remains 0.3.0, build 0 pending distribution destination/version validation.

Optional mesh alignment probe source is saved outside Unity assets in `Tools/Tests/AlignmentProbe/Assets/`. To reproduce overlay screenshots, copy that directory's contents into `Assets/` before a test build, then remove those copied files before a shipping build. The regular state walker does not need it.
